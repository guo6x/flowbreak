# FlowBreak 国内 Android 应用商店发行办理指南

**整理日期：2026-10-25。** 这是根据仓库内已有材料整理的决策与办理指南，不是对 2026-10-25 当天各平台规则的实时核验，也不是法律意见。它帮助发行负责人先了解要准备什么，再决定是否、以及在哪个渠道办理。

本文档只准备信息，不代表负责人已经决定发行。没有注册开发者账号、登录后台、实名认证、提交备案或软著申请、付款、上传应用、联系平台或发布应用。平台名称、页面入口、个人/企业准入、材料格式、费用和办理时限都可能变化，提交前须由发行主体在所选平台的官方入口核对。

### 开发者账号注册：通用步骤

以下步骤适用于“先选定一个市场再办理”的思路；每个平台界面、准入条件和验证方式不同，不能替代它自己的当前说明：

1. **选一个目标市场。** 先确认主要面向哪个渠道和地区；若仍在比较，只浏览该平台公开的开发者说明，不必提前创建账号。
2. **从官网找到开发者入口。** 使用上表的站内搜索词，在厂商官方网站内进入开发者/开放平台，再找“注册/开发者入驻/创建应用”等说明。检查地址栏和官方品牌信息，不从搜索广告或第三方代办入口开始。
3. **先读主体与类别要求。** 查清平台是否接受个人主体、是否接受工具/数字健康产品、要求哪些权限说明和资质。遇到 FlowBreak 的使用情况访问、悬浮窗、前台服务或无障碍能力，应先确认相应的申报路径；不能因为能注册账号就推断应用一定能过审。
4. **由实际权利人创建账号。** 按后台选定的个人/组织类型，使用真实信息完成该平台要求的邮箱/手机验证、实名或主体认证。支持邮箱 15015091629@163.com 已指定但未验证；是否同时作为登录邮箱由账号所有者决定，不要假设两者必须相同。
5. **保管账号恢复与管理员权限。** 账号所有者自己设置平台支持的双重验证和恢复方式。组织账号若支持成员账号/角色权限，由所有者添加负责上传的成员并授予最小权限；不共享主密码、验证码或恢复码。
6. **先停在资料核对阶段。** 本指南不创建账号、不代替本人读并接受服务条款、不提交实名认证、不付款。若后台要求付费或法律承诺，先由发行主体确认金额、条款和责任后再决定。

办理后只记录平台名称、账号主体类型、办理日期、当前状态和待办；不要把登录凭据、证件、私人联系方式或认证截图放入仓库。本次没有注册任何平台账号；负责人是否已有账号尚未核实，各平台规则未实时核验。未来如需侧载测试包，必须先取得发行负责人对具体测试的明确授权，并使用与测试目的匹配、来源和身份可核验的测试构建；这不等于授权生产签名、正式分发或商店发行。侧载不走商店后台，因此该测试安装步骤本身不需要商店开发者账号；但不免除适用的合规义务，也不代表当前候选包适合测试或发行。

有开发者账号只表示可以进入后台，不等于主体、应用类别、备案资质、权限声明或安装包已获批准。

**Google Play 是另一套独立渠道。** 它不是国内市场账号的通用替代品，也不是国内发行的必选步骤。如果将来要覆盖境外市场，再单独评估 Google Play 开发者账号、Data Safety、前台服务 specialUse 声明和平台审核。

## APP 备案和网站 ICP 备案不是同一件事

仓库已有资料引用了工信部 APP 备案相关通知，但没有据此确认 FlowBreak 这种以本机处理为主的产品具体适用哪种办理路径。是否需要办理、由谁作为主办者、通过哪个接入或分发平台提交，应由实际发行主体和拟投放渠道按当前官方要求确认。不要因“没有项目服务器”就自行宣称豁免，也不要把其他应用的备案号借来填。

APP 备案与网站/域名的 ICP 备案是不同事项，不能拿一个替另一个。没有自营服务器或域名时，不要为了一个尚未核实的字段随意购买云服务、域名或备案服务；先向所选渠道询问适用于本地运行应用的路径。政策网页的托管要求也不代表必须自建业务服务器。

### 经官方平台确认需要办理 APP 备案后的步骤

只有在选定的接入/分发平台确认办理入口、主办者和本应用的适用路径之后，才进入下面的流程。实际页面名称和字段以官方系统为准；任何字段若没有真实值，先停下询问，不要用假域名、借用备案号或空想的服务器信息凑表。

1. **确认办理主体与官方入口。** 由发行主体向已确认的网络接入/分发平台官方支持入口核实：谁是 APP 主办者、由哪个官方系统提交、已有账号还是需新建、是否要先完成主体实名认证。留存平台名称、日期和答复范围。
2. **准备资料清单。** 按该入口要求准备发行主体真实信息、经办人授权（如适用）、应用名称与简介、渠道和拟分发地区、包名、隐私政策 URL、业务服务器/网站/域名和接入方信息（若表格确实适用）、平台要求的备案或权属证明。个人证件、企业登记文件和住址只由主体在官方系统按需提交。
3. **核对最终应用身份。** 应用名、渠道、applicationId/包名和版本必须来自冻结后的最终候选，不要混用 Play 与国内包名。当前工程包名分别配置为 Play com.flowbreak.app 和国内版 com.flowbreak.app.cn，但发行提交前仍以最终构建实际读出的值为准。
4. **填写签名字段时区分证书摘要和公钥。** 如果系统分别要求签名证书 SHA-256、MD5 指纹、公钥或证书文件，逐项按字段提示从最终签名 APK/AAB 的证书读取公开值。SHA-256 和 MD5 是不同算法的摘要，不可互填；公钥/公钥证书也不是摘要，不能把指纹粘贴到公钥栏。可在授权的发行工作站使用 Android SDK 的证书校验工具检查最终 APK，例如：

   ~~~sh
   apksigner verify --print-certs FlowBreak.apk
   ~~~

   对已签名 AAB，可用 JDK 工具读取证书摘要，例如：

   ~~~sh
   keytool -printcert -jarfile FlowBreak.aab
   ~~~

   如果平台要求独立的公钥/证书文件，先确认具体格式，再从最终包的公开签名证书导出/读取。不要为了取得这些公开字段把私钥交给平台或协作者。
5. **填写服务器/域名及备案关系。** 如 FlowBreak 的真实架构没有自营业务服务器或网站，不要虚构 IP、域名、服务商或备案号。若表单字段必填，暂停提交，向接入/分发平台询问本地处理应用应如何如实填写、是否可走对应的本地应用路径；不要把隐私政策网页地址误填为业务 API 服务器，也不要把网站 ICP 备案号当 APP 备案号。
6. **逐项复核再提交。** 由主办者对照证件/登记文件、实际最终包名、公开证书值、隐私政策 URL 和渠道信息复核字面一致。保存提交回执和正式受理编号，不把身份证件或账户口令放进 Git 仓库。
7. **处理补正并等正式结果。** 收到补正时记录平台原文、截止时间和涉及字段，按真实资料修正后从同一官方入口提交。只有官方状态明确核准/完成后，才按平台要求使用正式备案信息或进入后续分发；提交成功、拿到受理号和正式核准不是同一个状态。

办理记录至少保留：官方入口/接入方名称、核实日期与答复、主办者类型、提交编号、当前状态、补正事项与期限、核准凭证位置。证件和账号材料只留在主体控制的合规存储中。若适用路径、无自营服务器的填法或必填字段仍不明确，停在咨询阶段；不要靠猜测填报或把“已提交”记为“已核准”。

这是一套保守的资料工作顺序，不是对所有省份、接入商或分发平台的统一表单说明。具体 APP 备案是否需要、字段叫什么、何时公示，均须通过选定平台的当前官方指引确认。

可以由发行负责人自行复制以下文字，发到所选平台**官方**的开发者服务/咨询入口；这只是问题模板，本指南没有替负责人发送：

>
> 1. 贵平台是否接受个人主体提交这类工具/数字健康类应用？是否有特定品类限制？
> 2. 对本应用，APP 备案由谁办理、通过哪个官方入口办理？平台对无自营服务器/域名的应用有何实际要求？
> 3. 网站 ICP 备案是否与贵平台要求的 APP 备案分别适用？隐私政策 URL 是否可使用稳定的静态托管页面？

> 5. Usage Access、悬浮窗、前台服务和国内版可选 Accessibility 各需提交哪些说明、演示或审核材料？
> 6. 申请主体所需的真实证件、授权文件、联系方式和账号验证材料有哪些？是否涉及结算或费用？请提供当前官方清单。

收到答复后记录平台名称、日期、答复范围和待补材料；答复只适用于该平台和该次咨询，不代表主管部门或其他商店的最终决定。

## 软件著作权：先核清权属，再按当期官方流程办理

仓库没有可据以宣称“软件著作权登记已完成”的证书。代码存在于仓库或已开源，不等同于某个发行主体已取得所有相关权利，也不代表任何应用商店一定要求登记证书。

若平台明确要求或权利人决定办理，可由实际权利人从中国版权保护中心软件登记官方渠道开始。不要通过来历不明的代理网站交证件或源代码；本指南没有联网核验该中心当前网页入口或表单版本，办理时请从其官方站点重新确认“计算机软件著作权登记”入口。

按这个顺序准备：

1. **确认权利人和贡献关系。** 列出实际作者、共同开发者、雇佣/委托开发关系、项目中已有的权利转让或授权约定。若有共同作者、公司职务成果、外包代码或历史合同，先由相关权利人核清谁有权申请和发行；不要把他人贡献直接填成单一主体独有。
2. **检查第三方内容和许可证。** 对照仓库的 **THIRD_PARTY_NOTICES.md**、依赖许可证和所使用的图片、字体、文案等来源，确认申请人对自己的部分有权申报，并遵守第三方许可。登记申请不能替代开源许可证义务，也不能把第三方组件说成独占自有成果。

## 隐私政策网页：有文稿，尚无已发布 URL

项目有 **PRIVACY.md** 和发布前核验稿，但正文仍需要发行主体信息、经确认的联系渠道和生效日期；公开 HTTPS 地址目前没有配置。因此现有仓库页面只能作为编辑材料，不能当作已经发布且审核通过的正式政策。

选择免费静态托管服务时，可按以下通用步骤操作；这里不替负责人启用 GitHub Pages，也不做任何部署：

1. **先确定最终政策文本。** 由发行主体填真实运营者名称、支持邮箱、政策生效日期、数据用途和用户删除方式；不要保留占位符。此步骤无需把身份证件或住址公开到网页。
2. **确认所选平台接受该类 URL。** 询问是否接受公共静态页面、是否要求独立域名、是否需在应用内展示。不要把“有 GitHub 仓库”当成 URL 已合格，也不要将分支预览页或需要登录的编辑页作为正式地址。
3. **由负责人创建静态页面。** 可评估既有官网或免费的静态站点托管（GitHub Pages 只是其中一个候选）。在服务方的官方帮助中按“创建站点/发布静态页面/启用 HTTPS”办理；发布内容只放经过确认的政策和公开联系信息，不加入无关统计脚本或私人资料。
4. **实测公开访问后再填表。** 用未登录窗口检查链接是否可打开、HTTPS 证书有效、正文版本正确；再从目标发行地区的普通网络和手机浏览器检查可达性，并确认网址不会随临时分支或一次性预览而失效。此项当前未执行，不能把候选链接写成已可用 URL。
5. **保存页面版本。** 记录公开 URL、发布时间、正文版本和源码 SHA；应用内“隐私政策”入口与商店填报应指向同一份现行内容。若平台要求网站域名/备案，而该静态托管方案不满足，先按官方答复更换路径，不要虚填。

只有完成未登录访问、有效 HTTPS、正文版本和目标地区可达性检查后，才把该 URL 作为正式政策地址；记录检查日期、网络/设备范围和页面版本。出现证书错误、登录墙、404、地区不可达或内容与应用不一致时先停下，不提交该地址。当前尚无已发布 URL，亦未执行上述验证。

发布前至少核对：发行主体名称和联系方式真实；说明本机处理的数据、权限用途、保留/删除方式、用户主动导出/分享的第三方接收边界；政策生效日期与实际版本一致；应用内可以找到该政策。FlowBreak 的诊断分享不包含目标应用清单和详细时间线，但仍可能显示制造商、导出时间和设备状态；完整数据导出范围更广。不能把“脱敏”写成“匿名”，也不能在最终安装包网络/SDK核查前承诺绝无网络请求。

## 从决定到提交：建议流程

1. **选一个渠道与地区。** 先选择准备试投放的市场，确认用户群和目标地区；Google Play 可单独放到以后评估。
2. **询问该平台当前准入。** 用上方模板询问个人/企业主体、工具品类、使用情况/悬浮窗/前台服务/Accessibility 材料、APP 备案和软件著作权要求。此时只咨询，不需要先注册全部账号或提交隐私身份材料。
3. **发行主体核清权属和证件。** 确认个人/组织权利人、开发者账号负责人、必要的授权关系，以及平台明确要求的备案/版权等资料。由主体在官方入口完成实名、账号条款和可能的付费步骤。
4. **验证支持邮箱并发布隐私政策。** 由负责人先验证邮箱能收信；填入已确认的主体信息，选择可访问的 HTTPS 托管，发布并检查目标地区能打开的最终政策页，再把真实 URL 写入商店表单和应用入口。
5. **经批准后冻结并制作最终发行包。** 仅在发行负责人明确批准正式发行、当前发布阻塞门禁已满足且授权流程允许后，才按 Gate G 流程冻结并签署最终包；本指南不构成该授权。届时精确记录源码 SHA、CI、渠道/包名、版本、二进制 SHA-256 与证书指纹，并在最终包上核实 Manifest、SDK/依赖和网络行为。沿用已记录的生产身份，不生成新密钥；当前候选保持 unsigned，不得当作已获签名或发行批准。
6. **准备商品页和审核材料。** 使用与最终包一致的图标、真实界面截图和所需演示；隐藏真实目标应用名单、联系人和通知内容。文案不得承诺所有机型可靠运行、绝对阻断或医疗效果。国内版 Accessibility 与 Play 版功能声明分开填写。
7. **由账号所有者在官方后台提交。** 由发行主体本人登录，录入主体、联系信息、隐私 URL、权限用途、内容分级和平台表单，上传匹配的最终安装包并查看预览后再点提交。本指南不登录、不代点提交、不接受平台条款。
8. **按真实审核意见修正。** 记录审核原因和涉及版本；若需修改代码或材料，重新构建、测试并更新 SHA/版本后按平台要求复审。提交成功、材料齐全或本地检查通过都不代表获准上架；平台可要求补充或拒绝，不能承诺通过日期。
