# PRODUCT — FlowBreak 产品行为规范

> 本文档是**唯一产品行为规范**：定义「现在产品应该怎么工作」。
> 不写开发历史、不写「以前怎么做」。涉及仍在修复中的缺陷时，使用「目标产品语义」与「Known deviations（当前基线）」两种状态分别标注。
> 当前文档基线：`99fdcc2f6f357e78fb70dd127adedfa31a098a71`（历史缺陷编号见 `KNOWN_ISSUES.md`）。

## 1. 产品定位与边界

- **定位**：本地运行的 Android 数字健康工具。在用户连续使用短视频/社交等目标应用达到限额时，通过渐进式提醒与可选强阻断，引导其主动休息；不惩罚、不制造内疚。
- **平台**：仅 Android（React/Capacitor 前端 + Java 原生服务）。iOS / Windows / macOS / Web PWA / 云同步 / 付费分层 / 家庭管理 / AI 推荐等均为**远期愿景**，不属于当前产品（历史蓝图见 `docs/archive/product/`）。
- **无账号体系**：不要求注册/登录。Login 页面为遗留占位页，启动流程不会进入真实登录。
- **无广告、无第三方统计 SDK**：所有数据仅保存在本机（详见 `PRIVACY.md` 与 `ARCHITECTURE.md`）。
- **当前不是医疗产品**：「休息效果」等指标只是本地短期行为记录，不代表治疗或长期健康改善。

## 2. 首次流程

1. Onboarding（3 页，可跳过）。
2. 权限页：**必需权限 2 项**——使用情况访问、悬浮窗。**两项必需权限必须都满足，才能继续首次设置流程**（「继续设置保护」按钮在缺失时禁用，并提示缺失项）。
3. 个性化页：选择连续使用限额（15/20/25/30/45 分钟，默认 25）、休息时长（2/3/5 分钟，默认 3）、是否允许每日一次紧急使用（默认开）。
4. 目标应用页：从应用列表中选择受限应用（搜索/清空/只看已选/已选置顶），**最多 30 个**，至少选 1 个。
5. 保存后启动保护（前台服务），进入 Dashboard。

## 3. 权限模型

| 权限 | 必需/可选 | 用途 |
| ---- | ---- | ---- |
| 使用情况访问（PACKAGE_USAGE_STATS） | 必需 | 识别前台应用、计算目标应用连续使用时长 |
| 悬浮窗（SYSTEM_ALERT_WINDOW） | 必需 | 在达到阻断条件时显示全屏覆盖页 |
| 通知（POST_NOTIFICATIONS） | 可选 | 前台服务状态与阶段提醒 |
| 电池优化豁免 | 可选 | 降低厂商后台限制导致的漏检 |
| OEM 自启动（跳转系统自启动管理） | 可选、条件显示（仅国内版 + 命中支持的 OEM 品牌） | 允许 FlowBreak 开机自启并加入后台白名单，避免被清理 |
| 无障碍服务（仅国内版） | 可选、实验性 | 命中已阻断应用时返回桌面并显示阻断页；仅处理窗口状态变化事件，不读取页面内容 |

规则：

- **必需权限缺失 → 阻塞「继续设置保护」**（首次流程无法继续，按钮禁用并提示缺失项）。
- **可选权限缺失 → 不阻塞首次流程**，可稍后补充。
- 自启动不是固定可选项，而是**条件性设置**：仅 Domestic 渠道 + 命中支持的 OEM 品牌时显示。支持的品牌含小米/红米/黑鲨、华为、荣耀、OPPO/一加/realme、vivo/iQOO、魅族、三星、乐视、华硕、中兴/努比亚、联想/摩托罗拉；标签按品牌生成，例如 Redmi/Xiaomi 设备显示「小米 / 红米 / 黑鲨 自启动」。

## 4. 目标应用

- 默认目标应用（首次进入时预置）：抖音 `com.ss.android.ugc.aweme`、B站 `tv.danmaku.bili`、快手 `com.smile.gifmaker`、微信 `com.tencent.mm`、小红书 `com.xingin.xhs`。
- 用户可自行增删，最多 30 个；所有已选目标应用**共享同一个连续使用限额**。
- 微信视频号识别（仅国内版）：目标语义是「微信内的视频号页面」可按视频应用参与阻断，依赖无障碍服务对页面 Activity 类名的识别；**当前为实验性能力，未在真机专项验证**，可能受微信版本变化影响。

## 5. 连续使用会话与状态机

状态机状态：`IDLE → PERCEPTION → COGNITION → BLOCKED → RESTING → GRACE → IDLE`。

- 前台服务每 **2 秒** 检查一次当前前台应用（`ARCHITECTURE.md`）。
- 目标应用在前台时，连续使用时长 `sessionMs` 按真实经过时间累计（单 tick 增量上限 10 秒）。
- 百分比 = `sessionMs / (limitMinutes × 60s)`：
  - `≥ 80%` → **PERCEPTION**（第一层，轻提醒）
  - `≥ 100%` → **COGNITION**（第二层，强提醒）
  - `≥ 120%` → **BLOCKED**（第三层，全屏阻断）
- 阈值百分比固定（80/100/120），由用户选择的限额分钟数换算成实际分钟（默认 25 分钟限额 = 20/25/30 分钟）。

### 目标产品语义（BLOCKED）

- 一旦进入 **BLOCKED**，阻断必须 **sticky**：普通离开目标应用**不能**解除 BLOCKED，也不应重置会话。

### TARGET / CURRENT RULE（30 秒 reset 的适用范围）

- 30 秒连续会话 reset **只适用于尚未进入 BLOCKED 的连续会话**（离开目标应用或熄屏超过 30 秒，重置的是普通连续会话计时）。
- 一旦进入 BLOCKED，以下行为都**不能**依靠「离开时间」解除 BLOCKED：
  - 普通离开目标 App
  - 长时间使用其他 App
  - 锁屏 / 解锁
  - 再次进入目标 App
- BLOCKED 只能通过产品定义的合法状态迁移退出：
  - 完成正式休息（获得 10 分钟访问窗口 GRACE）
  - 合法 Emergency Unlock（每日一次，长按 10 秒，获得 5 分钟 GRACE）
  - 明确定义的监控/配置生命周期转换（如用户关闭保护）
- 熄屏/锁屏期间不累计使用时长；普通离开会话的重置规则不得解除 BLOCKED。

### Known deviations（当前基线）

- 当前基线 `99fdcc2` 已通过 Redmi R1–R4 真机复测，与上述目标语义一致：BLOCKED sticky（R2）与冷启动前台追踪（R1）两个历史偏差已关闭（`FB-P1-01`、`FB-P1-02` → RESOLVED，见 `KNOWN_ISSUES.md`），当前无已知产品行为偏差。
- 兼容性观察（非产品行为偏差）：国内版 HyperOS 上 `tryStartBlockActivity` 尽力而为路径仍可能被系统拒绝（`COMPAT-001`，见 `KNOWN_ISSUES.md`），但不影响强阻断——无障碍顶部横幅独立可用。

## 6. 休息与解锁

- 进入 BLOCKED 后，覆盖页提供「开始休息」（进入 RESTING）与「紧急使用（长按 10 秒，每日一次）」。
- 休息时长：2/3/5 分钟（用户选择）。休息计时以**原生时间戳**校验；服务被杀后已实际超过所需休息时长时自动完成休息。
- 完整休息后：`RESTING → GRACE`，`graceUntil = now + 10 分钟`（`GRACE_MS`）。
- GRACE 到期自动回落 `IDLE`，sessionMs 归零。
- 提前结束休息**不会**解锁（不产生 GRACE）。

## 7. 紧急使用（Emergency）

- 每日最多一次（按自然日记录 `emergencyUnlockDay`）；同日第二次长按被拒绝。
- 长按 10 秒触发；成功后在本地数据库写入 `emergency_unlock` 事件（含时长 300 秒）。
- 解锁后进入 5 分钟 GRACE（`EMERGENCY_GRACE_MS`），到期回落 IDLE。

## 8. 渐进式干预与覆盖层

- PERCEPTION / COGNITION：顶部非阻断提示条（不拦截操作）。
- BLOCKED：全屏不透明遮罩（拦截输入），含「开始休息」「紧急使用（长按 10 秒，每日一次）」。
- 无悬浮窗权限或悬浮窗 addView 失败时，回退打开 `BlockActivity` 阻断页（尽力而为路径；国内版 HyperOS 上可能被系统「后台弹出界面」限制拒绝，但不影响强阻断，见 `KNOWN_ISSUES.md#COMPAT-001`）。
- 国内版无障碍强阻断：在 BLOCKED 且目标应用在前台时执行返回桌面（`GLOBAL_ACTION_HOME`），并显示无障碍顶部横幅（`TYPE_ACCESSIBILITY_OVERLAY`，单实例、重复命中不堆叠）；横幅提供「开始休息」等可操作入口，是独立于 `BlockActivity` 的可靠可见引导；仅处理窗口状态变化事件。

## 9. 统计与数据

- 只统计**已选目标应用**的当日前台时长（`getUsageStats` 基于 UsageEvents 配对算法，上限锁定为「今日 0 点至当前」）。
- 记录：每日使用聚合、每日统计、阻断尝试、休息完成、休息后是否回刷、成功拉回、紧急解锁事件、每日主观反馈（有帮助/一般/没帮助）。
- 效果验证：休息后创建独立 10 分钟观察窗口；未回刷，或回刷后主动离开全部目标应用满 30 秒，记为成功拉回。
- 本地数据导出：完整 JSON（设置、使用聚合、每日统计、事件、进度、本地界面缓存）；脱敏诊断导出（版本、渠道、服务心跳、权限、记录数量等，不含姓名、受限应用包名、具体使用明细）。
- 数据清除：先停止服务，再删除数据库与本地缓存。

## 10. Play / Domestic 渠道差异

| 项目 | Play 版 | 国内版 |
| ---- | ---- | ---- |
| applicationId | `com.flowbreak.app` | `com.flowbreak.app.cn` |
| 使用情况访问 / 悬浮窗 / 前台服务 | 支持 | 支持 |
| AccessibilityService 强阻断 | 不声明、不含 | 声明、可选开启（默认 UI 关闭） |
| 微信视频号识别 | 不支持 | 实验性（依赖无障碍服务） |

- Google Play 版清单不包含 `FlowAccessibilityService`。
- 无障碍服务业务处理仅接收 `TYPE_WINDOW_STATE_CHANGED` 事件（无障碍配置订阅窗口状态与窗口列表变化，代码只处理窗口状态变化），不读取页面内容、不记录输入。

## 11. 隐私原则

数据全本地：Web 界面层 `localStorage`，原生层 `SharedPreferences` + Room（数据库 schema v3）。不上传使用明细，不要求登录，可导出、可清除。详见根目录 `PRIVACY.md`。

## 12. 明确不在当前范围

- 定时休息提醒（按固定时间/间隔推送的提醒入口已被移除，当前只有「连续使用触发」式干预）。
- 疲劳生理检测（判定依据是连续使用时长，不是生理指标）。
- 积分/成就仅作为本地激励展示（完成休息 +10、成就解锁 +10），不构成付费或兑换体系。
- 多平台、云同步、账号、家庭管理、付费订阅。
